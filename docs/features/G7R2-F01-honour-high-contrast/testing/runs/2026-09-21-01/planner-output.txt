### Acceptance intent (#1)
1. With `accessibility.highContrast = true` in the effective settings, the product shell root carries a stable high-contrast marker (e.g. `data-contrast="high"`) and high-contrast token overrides take effect across dashboard surfaces.

3. The value resolves through the existing member → org → global → default chain (no new resolution logic).
4. Change is keyboard- and screen-reader-neutral; overrides meet WCAG 2.2 AA contrast where they alter foreground/background pairs.
5. Unit test asserts the marker/override toggles with the value; e2e test flips the setting and asserts the DOM marker at desktop and mobile width with no console errors; accessibility-QA confirms contrast ratios.
